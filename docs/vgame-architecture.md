# Vgame integration and compatibility

The repository is a React/TypeScript/Vite browser application with Zustand state and IndexedDB storage. Provider adapters support KoboldCpp, OpenAI-compatible completions, AI Horde, OpenRouter and NanoGPT. Existing generation separates exposed reasoning and maintains manuscript undo/checkpoints. Project version 2 uses delta-packed prose, and credentials live separately in browser local storage.

Vgame is an optional `Story.vgame` version-1 project, not a replacement for those pipelines. `MainSettings` persists the workspace choice as an independent browser preference. Vchat text, segments, snapshots, note updates, Writer's Block and FF 5.4 remain available unchanged. First entry creates a separate page from the current prose. Existing projects need no migration beyond absence meaning an uninitialized game. Full story import validates game data before accepting it; loading clears transient generation locks. The user's original text is never rewritten by game navigation or game undo.

The layers are `vgame/parser.ts` (tokens, recursive AST and spans), `runtime.ts` (allowlisted semantic validation and transactions), `state.ts` (canonical project, compact history, validation), `ai.ts` (context/transport/proposals), and `GameWorkspace` (safe React widgets and both editor paths). Source drafts are not a second persisted model: Preview uses a copy, Apply commits the same canonical project used by visual editors. Definition mode updates existing IDs and preserves omitted definitions. Explicit deletion/replacement requires review. Exported source omits large/archived prose with comments; full project/checkpoint JSON preserves it.

Ordered option actions validate atomically before committing. A scheduled AI action is deduplicated and locked; its later narrative is a separate revision. Cancellation leaves deterministic option effects intact. Undo restores state without calling the provider again. Browsing a page is navigation, not an implicit rewind. Restoring a revision and branching are explicit operations.

AI uses the existing connection and credential registry with independent game context/output/thinking allowances. The prompt contains an engine contract, supported syntax, profile, scoped author directions, protected context, approved world state, current-page prose, budget-fitting recent pages and optional manual summaries. Lower-trust prose/lore is data, not command authority. Player-only descriptions and unreadable objects are omitted; pending proposals are not facts. No provider key is copied into a game or export.

Response envelopes are validated before anything is committed. A model may return zero proposals or ordinary prose. Only explicit structured proposals are parsed as source. Manual is the default; Smart recognizes routine permitted set/modify operations, and Auto still enforces ownership/access and destructive confirmation. Approval revalidates current references and dependency bundles atomically. Invalid commands remain failed audit entries. Root AI requests never auto-chain recursively.

State scope and UI scope are separate. Widgets bind existing values; creating a value does not automatically display it. Global views persist within the project, page views belong to their page, and event views follow active events. Ending a view never silently deletes bound state. Encounter probability is evaluated only by explicit hooks with saved deterministic randomness and cooldowns, never React render cycles.

The initial implementation covers the design's core phases 1–5 plus selected conditions/hooks/encounters. The command matrix in [the grammar reference](vhtml.md) distinguishes executable commands from future parsed names. There is no eval, arbitrary HTML/CSS/JS, filesystem access, external-code import, automatic summary service, clock scheduler or generic plugin engine. Runtime size/depth/count guards and the retained-history limit are explicit rather than silently deleting archives. The project guard measures serialized JSON UTF-16 code units (40 × 1,024²), while checkpoint upload checks bytes (128 MiB). This accounts for Unicode encoding and keeps valid compact exports importable.
